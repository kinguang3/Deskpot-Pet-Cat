# GBC Nina v0.1.2

> 发布日期：2026-10-10
> 上一版：v0.1.1（提交 `4b31f78` 打 tag；实际发布包构建于 `6b06960`）

一只住在你桌面上的小猫。本版本以**修复**为主：修掉了一个「点她没反应」的严重回归，把用户数据彻底搬进 `%APPDATA%`，并补上了麦克风选择能力。

## 亮点

- **点击不再无响应** —— v0.1.1 的 tag 里没有这段代码，但**已发布的那份 zip 有**：PySide6 6.11 下 `Qt.MouseButton` 与 `int` 比较恒为 `False`，左键单击与右键全部失效，只剩双击能用。本版本做根因修复。
- **用户数据搬到 `%APPDATA%\GBC Nina\`** —— 程序目录变为纯只读，装到 `C:\Program Files` 或解压到系统盘都不会再出现「设置保存失败 / 互动记忆丢失」。
- **麦克风可选 + 实时电平** —— 设置页新增设备下拉框与「测试」电平条，静音设备一目了然；多声道麦克风阵列自动下混为单声道，不再被直接拒绝。
- **新增 Inno Setup 安装器脚本** —— 可编译 `setup.exe`（安装目录可选、快捷方式、开机自启、便携模式、卸载时可选清数据）。

## 新增

- **麦克风选择与实时电平测试**：设置 → 语音指令 →「麦克风」下拉框列出全部输入设备（含声道数），点「测试」实时显示 0~100% 电平条。设备按**名称**保存到 `voice.input_device`，重启 / 拔插后按名称重新匹配，不会因 PortAudio 索引漂移而错选。
- **多声道自动下混**：麦克风阵列等多声道设备按设备实际声道采集后下混为单声道再送分段与识别。此前按单声道请求阵列只会拿到静音的第 0 声道，表现为「系统里明明有信号，软件里录不到」。
- **Inno Setup 安装器**（`GBC.Nina.installer.iss`）：支持自定义安装目录、桌面 / 开始菜单快捷方式、开机自启、便携模式（程序旁写 `portable.txt`，数据存 U 盘），卸载时询问是否一并删除 `%APPDATA%` 下的用户数据。
- **旧数据自动迁移**：首次启动把旧版写在安装目录的 `config/user.json` 与 `data/`（互动记忆、SenseVoice 崩溃标记）一次性迁到用户数据目录；只复制目标不存在的文件，幂等且**绝不覆盖**新数据。

## 修复

- **点击 Nina 无反应（严重）**：`Qt.MouseButton` 与 `int` 比较在 PySide6 6.11 恒为 `False`，导致左键 / 右键事件被全部丢弃——点她不开心、点不醒睡猫、互动计数不涨都是这一个原因。改为枚举比较（`src/interaction/mouse.py`、`src/core/pet.py`）。
- **双击同时触发两套反应**：单击在双击窗口内被立即发出，一次双击会同时触发「点击反应」与「打字动画」。改为延迟一个双击窗口再发单击，收到双击即取消待发的单击。
- **时段行为权重启动时被冻结**：时段修正系数只读构造时缓存的值，导致上午启动就整天按「白天」权重、深夜启动则永远是深夜权重。改为每次取值前刷新。
- **打开设置必弹「确定开启语音？」**：载入配置时的程序化勾选也走了确认框分支，语音开启状态下每次打开设置面板都被拦一次。
- **Nina 倒着走**：撞到屏幕边缘折返后只翻转移动方向、没切换行走动画，出现「播放 walk_left 但实际向右走」。`Pet.set_facing()` 现在会同步切换为与朝向一致的那一套动画。
- **SenseVoice 每句话都重崩一次**：崩溃标记迁到 `%APPDATA%` 后未兼容旧路径，标记被静默忽略，真实语音每句都要先崩一次（约 5 秒）才回落云端。改为新旧路径双查并自动迁移；同时修掉标记目录不存在导致写入失败（标记永远存不下来）的问题。
- **便携模式永不生效**：安装器把 `portable.txt` 写在 exe 同级，代码却只查 `_internal\`。现在两个位置都查。
- **隐私协议 / 保存失败文案过时**：数据已迁至 `%APPDATA%`，两处文案仍指向「程序目录 / Program Files」，会误导用户去错误的位置找数据。
- 文档滞后：README Q8 描述的「拒绝多声道麦克风」已被自动下混取代、`docs/voice.md` 配置示例与实际默认值不一致（`enabled`、`assemblyai.language`）。

## 工程与清理

- **死代码清理（两轮）**：删除全仓库零调用成员约 90 处——`Memory` 10 个、`EmotionSystem` 7 个、`CommandManager` 7 个、`DialogueContent` 16 个台词方法及对应数据，以及 `VoiceManager` / `AudioCapture` / `SpriteLoader` / `AnimationManager` / `EventBus` / `StateMachine` / `Storage` / `ConfigManager` 中未接线的成员与 `PetWindow` 三个从未被 `connect` 的 Qt 信号。
- 删除从未使用的素材 `assets/cat_tall.png`、`cat_long.png`、`cat_melt.png`、`cat_glitch.png` 及随之失效的 `SINGLE_FRAME_MAP` 加载路径。
- 删除依赖不存在音频文件的临时脚本 `test.py` 与已过时的调试文档 `VOICE_WAKE_DEBUG_LOG.md`、零引用的 `fbank_lfr_cmvn_feature.json`。
- 版本号三处不一致（`config/default.json` 的 `app.version`、`src/__init__.py` 的 `__version__`、`main.py` 的 `setApplicationVersion` 均停留在 0.1.0）统一为 0.1.2；打包脚本更名为 `GBC.Nina.v0.1.2.spec`。
- README 新增 Q11 记录本版本变更，Q8 重写为麦克风无声排查指引。

## 已知限制

- **本地 SenseVoice 引擎在部分机器上不可用**：`bin/sense-voice-main.exe` 对真实语音 100% 访问冲突（`0xC0000005`），与线程数、GPU 开关、beam 参数、语言设置均无关。首次冲突即自动禁用并写入标记，后续启动直接跳过；标记绑定 exe 与模型的「大小 + 修改时间」指纹，替换二进制或模型后自动恢复。降级期间转写与语音指令仍可用（走云端）。
- **中文情绪恒为 `UNKNOWN`**：AssemblyAI 的情绪分析仅支持英语，默认 `voice.assemblyai.language` 为 `zh`（保中文转写质量），因此云端极性情绪不会启用。这是已知限制而非配置错误；想启用需改为 `en`，但中文转写质量会下降。
- 安装器脚本未经实际编译验证（本机未安装 Inno Setup），zip 包不受影响。
- `assets/cat_typing_red*.png` 仍在包内但没有任何代码播放它（`ANIMATION_MAP` 有声明、无调用点）。

## 升级说明

- **直接解压新 zip 覆盖即可**，用户数据不会丢：首次启动自动把旧 `data/`、`config/user.json` 迁到 `%APPDATA%\GBC Nina\`；已迁过的再次启动是空操作。
- 旧版本已同意隐私协议的用户不会再次被弹协议。
- 便携模式标记现在同时识别 exe 同级与 `_internal\`，两种放置方式都有效。
- 清理数据：用户数据在 `%APPDATA%\GBC Nina\`，只删程序目录**不会**清除记忆与设置；需要彻底清除请手动删除该目录。
